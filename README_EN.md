AI Core assembles preprocessing, inference, and postprocessing pipelines from
plugins. It supports ONNX Runtime, NCNN, TensorRT, and out-of-tree backends.

## v2 dependency boundary

The default build contains only `libai_core`. It does not discover, compile, or
link any third-party library; its dynamic dependencies are limited to the C++
and operating-system runtimes. Config, each maintained plugin, and developer
tooling are independent opt-in components. A dependency is resolved only when
the component that owns it is enabled.

- `third_party/config/`: config source dependencies.
- `third_party/plugins/`: maintained plugin source dependencies.
- `third_party/testing/` and `third_party/benchmarking/`: developer-only code.
- `.deps/<OS>_<ARCH>/`: ignored prebuilt SDKs such as ONNX Runtime, NCNN, and
  TensorRT.

Every submodule is pinned by its gitlink commit. Do not initialize the entire
tree recursively; use `scripts/deps.sh init <profile>`.

## Quick start

Build the zero-third-party core:

```bash
git clone https://github.com/sinterwong/ai-core.git
cd ai-core
cmake --preset core
cmake --build --preset core
cmake --install build/core
```

Initialize only the profiles needed by a component build:

```bash
# JSON config
scripts/deps.sh init config
cmake --preset config
cmake --build --preset config

# OpenCV plugins using the repository-pinned provider
scripts/deps.sh init vision
cmake --preset vision
cmake --build --preset vision

# Common developer build: config + vision + ONNX Runtime + tests.
# This preset uses system OpenCV.
scripts/deps.sh init config onnxruntime testing
cmake --preset developer
cmake --build --preset developer
ctest --preset developer
```

For a one-command developer build, `scripts/bootstrap.sh` defaults to the
pinned bundled OpenCV. Pass `--opencv-provider SYSTEM` to use system OpenCV.

```bash
scripts/bootstrap.sh
```

Profiles are `core`, `config`, `vision`, `onnxruntime`, `ncnn`, `tensorrt`,
`decryption`, `testing`, `benchmarking`, and `developer`. NCNN and TensorRT do
not have universal public binary downloads. Supply SDK tarballs through
`AI_CORE_NCNN_ARCHIVE` and `AI_CORE_TENSORRT_ARCHIVE`, or set their CMake roots
directly.

## CMake options

Every option defaults to `OFF`.

| Option | Description |
| --- | --- |
| `AI_CORE_BUILD_CONFIG` | Build the JSON config module |
| `AI_CORE_BUILD_PLUGIN_PREPROC_OPENCV` | Build the OpenCV preprocessing plugin |
| `AI_CORE_BUILD_PLUGIN_POSTPROC_OPENCV` | Build the OpenCV postprocessing plugin |
| `AI_CORE_BUILD_PLUGIN_ONNXRUNTIME` | Build the ONNX Runtime plugin |
| `AI_CORE_BUILD_PLUGIN_NCNN` | Build the NCNN plugin |
| `AI_CORE_BUILD_PLUGIN_TENSORRT` | Build the TensorRT plugin |
| `AI_CORE_ENABLE_MODEL_DECRYPTION` | Add decryption to enabled inference plugins |
| `AI_CORE_BUILD_TESTS` | Build dependency-partitioned tests |
| `AI_CORE_BUILD_BENCHMARKS` | Build benchmarks |
| `AI_CORE_BUILD_EXAMPLES` | Build examples (requires config) |

Dependency location settings:

- `AI_CORE_OPENCV_PROVIDER=BUNDLED|SYSTEM`, default `BUNDLED`.
- `AI_CORE_DEPS_ROOT`, default `.deps/<OS>_<ARCH>`.
- `AI_CORE_ONNXRUNTIME_ROOT`, `AI_CORE_NCNN_ROOT`, and
  `AI_CORE_TENSORRT_ROOT`.
- `AI_CORE_CUDA_ARCHITECTURES`.

A missing dependency fails during configure with its exact path, provisioning
profile, and root override. Discovery does not scan implicit fallback SDKs.

## Tests

```bash
scripts/deps.sh init testing
cmake --preset core-tests
cmake --build --preset core-tests
ctest --preset core-tests

# Labels: core / config / vision / backend
ctest --test-dir build/developer -L backend --output-on-failure

scripts/coverage.sh
```

Enabling tests alone builds only the core suite and does not bring in OpenCV or
an inference SDK. Model assets are used only by backend integration tests.
Machine-specific TensorRT engines are generated by `scripts/fetch_models.sh`.

## Install and consume

Install components are `runtime`, `development`, `config`,
`plugin-preproc-opencv`, `plugin-postproc-opencv`, `plugin-onnxruntime`,
`plugin-ncnn`, `plugin-tensorrt`, `tests`, `benchmarks`, `examples`, and
`assets`.

```cmake
find_package(ai_core 2.0 REQUIRED COMPONENTS core config)
target_link_libraries(my_app PRIVATE ai_core::ai_core ai_core::config)
```

Plugin targets are exported as `ai_core::plugin_preproc_opencv`,
`ai_core::plugin_postproc_opencv`, `ai_core::plugin_onnxruntime`,
`ai_core::plugin_ncnn`, and `ai_core::plugin_tensorrt`. The package variable
`ai_core_PLUGIN_DIR` names their runtime directory. Out-of-tree plugins can use
`ai_core_add_plugin()` from the installed `AICorePlugin.cmake`.

## Usage and documentation

Applications explicitly load the required plugins through `PluginManager`,
then assemble the three registered stages with `AlgoInference`. Public API
headers expose no third-party types; OpenCV conversion is opt-in through
`<ai_core/opencv_interop.hpp>`.
